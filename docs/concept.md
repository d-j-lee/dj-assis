# dj-assis — 개념 (정본)

> 사람과 실작업 AI 사이에 **다리를 놓는 AI 비서**. 실작업 AI의 세션 품질을 최선으로 관리한다.
> 접근성 좋은 안드로이드 폰의 Claude 앱에서, 말로 쓴다.
>
> 이 문서는 "무엇을·왜"의 정본이다. "어떻게"는 [`architecture.md`](architecture.md),
> 결정 이력은 [`decisions.md`](decisions.md).

## 1. 계기 — 이제 사람이 병목이다

AI는 이미 충분히 유능한데, 발전 속도를 사람이 따라가지 못하는 **지체**가 생겼다.
부족한 인지로 쓴 프롬프트, 불필요한 노이즈, 이해가 덜 된 상태의 부적절한 피드백이 오히려
세션 품질을 깎는다. 깎이는 경로는 셋이다.

| 경로 | 증상 | 결과 |
|---|---|---|
| **입력** | 목표·완료 기준·제약이 빠진 얇은 프롬프트, 생각나는 대로의 지시 | 워커가 추측으로 메움 → 엉뚱한 방향·과잉 구현 |
| **중간 피드백** | 맥락을 다 보지 못한 채 하는 반응적 지시. 워커는 최근 입력을 과대 반영한다 | 컨텍스트 오염, 방향 흔들림, 앞선 합의 덮어쓰기 |
| **결과 소비** | 밀도 높은 출력을 다 읽지 못함 | 고무도장 승인, 또는 오판 |

근거도 같은 방향이다. 한 번에 주면 풀던 과제를 여러 턴에 나눠 주면 LLM 15종의 성능이 평균 39%
떨어지고, 모델은 초기 가정에 고착해 회복하지 못한다(F1). 사람이 생각나는 대로 조금씩 던지는
지시가 바로 그 형태다. 실사용 계정 하나를 표본으로 재 보니 Claude Code 세션 22개 중 12개가
사람을 기다리고 있었고, 그중 8개는 2주 넘게 방치돼 있었다 `[실측 2026-10-18, 표본 1]`.

## 2. 구상 — 사람과 워커 사이에 비서를 둔다

사람과 AI 사이를 **층으로 나누고**, 그 층이 양쪽을 각자에게 맞게 옮겨 준다.

| # | 원 구상 | 비서가 하는 일 | 원칙 |
|---|---|---|---|
| ① | 무슨 작업을 원하는지 **음성으로 직관적으로** 입력 | 말을 그대로 받고, 노이즈를 걷어 의도를 뽑는다 | P5 |
| ② | **사전 검토**, 인터뷰로 **최선의 최종 프롬프트**를 짜서 작업을 이끈다 | 빈칸만 짧게 묻고 의도 계약으로 굳힌 뒤, 워커용 지시서로 컴파일해 투입한다 | P1·P2·P3 |
| ③ | **주요 시점마다** 능동적 브리핑, 이후 **진행 방향 가이드** | 워커 진행을 증거로 읽고, 사람이 결정할 것만 골라 올린다. 다음 방향을 추천과 함께 제시한다 | P4·P6·P7 |
| ④ | 비서→사람: **음성 + 직관적 브리핑 자료**로 최종 의사결정을 돕는다 | 음성은 한 호흡 헤드라인과 질문, 화면은 증거와 선택지 | P5·P9 |
| ⑤ | 비서→워커: **전체 방향과 현 시점에 맞는** 프롬프트 | 사람의 답을 해석해 되읽고, 계약 갱신분만 정리해 전달한다 | P2·P8 |

③의 중재는 맞춤이다 — **실작업 AI의 작업 수준**(얼마나 맡겨도 되는가)과 **사람의 인지 부하**
(지금 얼마나 받아들일 수 있는가) 사이에서 깊이와 시점을 고른다.

```
 사람 (저대역·고의도·음성·폰)            워커 AI (고대역·명시적 지시 필요·컨텍스트 민감)
        │   ▲                                         ▲   │
 음성·말 │   │ 결정 카드(음성 헤드라인 + 화면 증거)          │   │ 진행·산출물·질문
        ▼   │                                         │   ▼
   ┌──────────────────────── dj-assis ────────────────────────┐
   │ 정방향: 노이즈 제거 → 인터뷰 → 의도 계약 → 지시서 컴파일 → 투입   │
   │ 역방향: 증거 수집 → 요약·판단 → 결정이 필요한 것만 올림          │
   │ 방화벽: 사람의 중간 피드백을 분류·정합한 뒤에만 워커로           │
   └──────────────────────────────────────────────────────────┘
```

## 3. 설계 원칙

근거 번호(F1…)는 [`research/20261018-foundation.md`](research/20261018-foundation.md) §3.

| # | 원칙 | 이유 | 근거 |
|---|---|---|---|
| P1 | **사람은 프롬프트가 아니라 계약을 승인하고, 워커에는 한 번에 넘긴다** | 오가는 대화는 비서가 흡수한다. 워커는 새 세션에서 완결된 지시서 하나를 받는다 | F1·F4 |
| P2 | **단계가 아니라 의도로 지시한다** | 목표·이유·끝 상태·제약·비목표·검증 방법까지만. 유능한 워커에게 과잉 지시는 품질을 떨어뜨린다. 사람 원문은 부록으로 붙여 표류를 잡는다 | F6·F7 |
| P3 | **중개 깊이는 적응형, 질문에는 예산이 있다** | 먼저 스스로 조사하고, 사람만 아는 것만 묻는다. 질문마다 추천 기본값. 한 문장짜리 일엔 질문 0개 (L0 통과 / L1 다듬기 / L2 인터뷰+계약 / L3 체크포인트 운영) | F5·F12 |
| P4 | **행동이 아니라 결정을 게이트한다** | 비가역·범위 변경·사람만 아는 입력·최종 수용만 올린다. 행동 단위 승인은 97%가 그냥 통과돼 의미가 없다 | F3·F8 |
| P5 | **음성은 헤드라인, 화면은 증거** | 음성은 한 호흡, 질문으로 끝낸다. 식별자·숫자·표는 화면에만, 둘이 같은 말을 반복하지 않는다. 입력은 말이 3배 빠르고 출력은 읽기가 빠르다 | F2·F11 |
| P6 | **끼어들기에도 예산을 둔다** | 작업 이정표의 굵은 경계에서 묶어 올린다. 되돌릴 수 있는 결정은 기본값으로 진행하고 기록만 | F9 |
| P7 | **증거 없는 주장은 올리지 않는다** | 모든 상태 주장은 도구 결과에 출처가 있다. 확인 못 한 건 확인 못 했다고 쓴다 | F8 |
| P8 | **피드백은 대화가 아니라 계약 수정이다** | 사람의 중간 피드백은 해석을 한 줄 되읽은 뒤 계약에 반영한다. 두 번 고쳐도 안 되면 새 세션에서 깨끗하게 다시 | F4·F8 |
| P9 | **고무도장을 경계하고 사람을 키운다** | 결정마다 실질 선택지를 주고, 고위험은 말 한마디 "네"가 아니라 화면에서 명시적으로 고른다. 거절률이 0에 가까우면 경고 신호 | F3·F10 |
| P10 | **얇게 시작하고, 효과로 증명한다** | 플랫폼이 매주 진화한다. 측정된 공백만 직접 만든다. 체감 속도가 아니라 결과로 비교한다 | F9·F12 |

## 4. 하지 않는 것

- 워커를 대체하지 않는다. 비서는 직접 구현하지 않고 위임·중재만 한다.
- 사람의 결정권을 가져가지 않는다. 비가역·범위 변경·사람만 아는 입력은 항상 사람에게 간다.
- 플랫폼이 이미 주거나 곧 줄 인프라(음성 인식, 세션 실행기, 알림)를 다시 만들지 않는다.

## 5. 가장 큰 위험 셋

| 위험 | 모습 | 대응 |
|---|---|---|
| 의도 표류 | 컴파일된 지시서가 말한 뜻과 조용히 어긋나고, 문자 그대로 따르는 워커가 충실히 틀린다 | 가정 목록 한 줄 되읽기, 원문 부록, 구조화된 필드로 컴파일, 모순은 워커가 해결하지 말고 보고 |
| 고무도장 | 비서의 추천이 곧 결정이 되고 사람은 시스템을 놓친다 | 결정 수를 줄이고 하나하나 실질 선택으로, 거절률 관찰 |
| 비서가 병목 | 질문 폭증·왕복 지연·사용량 증가 | 질문 예산, 기본값 진행, 사소한 일은 L0 통과 |

## 6. 용어

| 용어 | 뜻 |
|---|---|
| 의도 계약 (Intent Contract) | 목표·이유·완료 기준·제약·비목표·결정권을 담은 작은 문서. 사람이 승인하는 유일한 대상 |
| 컴파일 | 계약 + 작업 맥락 → 워커 수준에 맞춘 지시서 생성. 언제든 다시 할 수 있다 |
| 결정 카드 (Decision Card) | 결론 한 줄 + 결정 하나 + 추천안 + 되돌림 가능성 + 무응답 시 기본값 + 증거 링크 + 다음 방향 |
| 체크포인트 | 워커 진행 중 사람의 판단이 필요한 지점. 계약에 미리 선언하거나 비서가 감지한다 |
| 중개 깊이 L0~L3 | P3의 4단계. 요청마다 비서가 고르고 사람에게 한 단어로 알린다 |
| 데스크 | 비서가 사는 표면(세션·페이지). 표면은 바뀌어도 계약·상태는 같다 |
