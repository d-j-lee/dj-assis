# 예시 — 두서없는 말 한 덩어리를 지시서 한 장으로

> 합성 사례다(실제 사용자·리포가 아니다). 변환의 **수준**을 보여 주려는 것이지 문장을 베끼라는 것이 아니다.

## 1. 원문 (받아쓰기 그대로)

> 어 그 가계부 앱 있잖아 거기 월별 그래프가 좀 이상한 거 같은데 지난달 거랑 합계가 안 맞는 거 같기도 하고
> 아 그리고 다크모드도 했으면 좋겠는데 일단 그래프부터 봐줘 급한 건 아니고 주말 전에만

## 2. 받기 · 깊이

- 요청 A: 월별 그래프 합계가 실제 합계와 다른 것 같다 → **이번 접수**
- 요청 B: 다크 모드 → "따로 접수할까요?" (사용자: 나중에)
- `요지: 가계부 앱 월별 그래프의 합계 오류를 주말 전까지 고친다`
- 깊이 **L2** — 버그인지 표시 방식 차이인지 모호하고, 원인에 따라 데이터를 고쳐야 할 수도 있다(되돌리기 어려움)

## 3. 사전 검토 (묻기 전에)

- 대상 리포: `list_repos`에 가계부 리포가 하나뿐 → 묻지 않음
- 겹치는 세션: 없음
- 리포 README: 월별 집계는 서버에서, 그래프는 클라이언트에서 그린다 `[실측: README]`

## 4. 인터뷰 (1묶음, 3문항)

| 질문 | 선택지 (추천 먼저) | 답 |
|---|---|---|
| 무엇과 비교해 안 맞았나요? | 거래 목록 합계(추천) / 은행 앱 / 기억 | 거래 목록 합계 |
| 원인이 저장된 데이터 쪽이면? | 멈추고 보고(추천) / 고쳐도 됨 | 멈추고 보고 |
| 완료는 무엇으로 볼까요? | 지난 3개월 그래프 = 거래 목록 합계(추천) / 이번 달만 | 추천대로 |

## 5. 의도 계약

```
[의도 계약 v1 · 2026-10-18]
목표: 월별 그래프의 합계가 거래 목록 합계와 같아진다
왜·누구를 위해: 사용자가 지출을 그래프로 판단하는데 숫자가 틀리면 앱을 믿을 수 없다
끝 상태: 최근 3개월 각각 그래프 합계 = 거래 목록 합계
검증 방법: 3개월치를 비교하는 테스트를 추가해 통과 / 화면에서 지난달 값 대조
범위 밖: 다크 모드, 그래프 디자인 변경, 저장된 거래 데이터 수정
결정권: 혼자 정해도 됨 — 집계·표시 코드 수정, 테스트 추가 / 멈추고 물을 것 — 저장 데이터가 원인일 때, 화면 동작이 바뀔 때
체크포인트: 원인을 찾은 시점에 한 번, 끝에서 한 번
제약: 주말 전
맥락: 집계는 서버, 그래프는 클라이언트 [실측: README]
가정: 기준 통화·시간대는 앱 설정값 그대로 / "합계"는 지출만(수입 제외)
깊이: L2
```

🔊 *"지난 석 달 그래프 합계를 거래 목록과 맞추는 일, 이대로 맡길까요?"* → 승인

## 6. 지시서 (발췌)

```
이 작업은 dj-assis(사용자의 중개 비서)가 사용자와 합의한 의도 계약에 따라 맡기는 것이다. …

## 왜
사용자는 지출을 월별 그래프로 판단한다. 그래프 합계가 거래 목록과 다르면 앱 전체를 믿지 못한다.
집계는 서버, 그래프는 클라이언트에서 그린다(README).

## 끝 상태
최근 3개월 각각 그래프 합계 = 거래 목록 합계.
확인 방법: 3개월치를 비교하는 테스트를 추가해 통과시키고, 지난달 값을 화면 기준으로 대조한다.

## 범위
- 하지 말 것: 다크 모드, 그래프 디자인 변경, 저장된 거래 데이터 수정
- 멈추고 물을 것: 원인이 저장 데이터일 때, 화면 동작이 바뀔 때 …

## 체크포인트
원인을 찾으면 고치기 전에 한 번 보고, 끝에서 한 번.
…
## 부록 — 사용자 원문
"어 그 가계부 앱 있잖아 …"
```

## 무엇이 달라졌나

| 원문 | 지시서 |
|---|---|
| 요청 두 개가 섞임 | 하나만, 다른 하나는 명시적으로 범위 밖 |
| "이상한 것 같다" | 무엇과 비교해 틀렸는지, 무엇이면 끝인지 |
| 데이터 수정 여부 미정 | 위험한 갈림길에서 멈추고 묻도록 |
| 방법 지시 없음 | 방법은 여전히 워커에게 — 의도만 넘김 |
